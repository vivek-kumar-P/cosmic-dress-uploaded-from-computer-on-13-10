# docs/guides/

**Purpose:** Practical how-to guides for working on this project day-to-day.
**Audience:** All contributors.

## Contents

| File | Description |
|------|-------------|
| [`LOCAL_DEVELOPMENT.md`](./LOCAL_DEVELOPMENT.md) | Full local setup, dev server, debugging tips, and documentation update rules |
| [`TESTING.md`](./TESTING.md) | Testing strategy — manual verification checklists and future automated test plan |

## Rules

- Guides are practical and task-focused. They answer "how do I do X?" not "why does X exist?"
- Architecture explanations belong in `docs/architecture/`, not here.
- Keep guides short enough that a developer can follow them in one sitting.
